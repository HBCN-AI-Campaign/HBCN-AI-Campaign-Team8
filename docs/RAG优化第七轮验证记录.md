# RAG 优化第七轮：用途与法规适用性约束

> R08/R12 部分实现；2026-10-22。仍在持续目标内，不代表整体法规、业务质量或部署验收完成。

## 变更与复审

问答、流式问答和增强检索共用 `purpose` 与严格 `legal_context`。默认 reference 仅参考；case_assessment 明确业务日期、辖区、主体和业务类型。结构化条件提供给规划/评估/生成/复核模型作为上下文，不作为法规证据。新增服务端复核文件，与法规原文/父片段哈希、来源版本绑定，按业务时点的有效区间、当前复核期限和适用范围检查。上传元数据及法宝“现行有效”不能自行批准。

复审修复三处边界：

1. 法规判断漏选法规原文时，不能只选内部规则绕过门禁；明确法规范围、规划识别 law 或显式请求法宝时要求法规原文。
2. 同一正文但来源效力状态变化，旧复核不能继续生效；除原文哈希外绑定来源版本。每次重新读取复核文件，撤销后下一请求不能使用进程旧缓存。
3. 本案门禁失败时，问答也保留已选参考片段和 missing，跳过生成；此前仅增强检索保留此类部分依据。grounding/evidence_status 仍为 insufficient，不把“有来源”当成已核验。

文档与机器契约：[法规复核台账契约](RAG法规复核台账契约.md)、[JSON Schema](../code/rag-service/app/contracts/legal-review-registry.schema.json)。规划、模块总览及总体/检索图同步增加此独立门禁，当前架构与目标架构继续分开。

## 未完成项与下一轮

台账当前没有真实配置，不能给实际案件填造批准记录。复核人员身份认证、审批/审计流程、真实法规过渡条款、法规变更订阅、时态召回/过滤和分布式撤销传播未完成；复核范围匹配不是法律/信贷批准。默认参考模式的语义越界目前依赖模型指令，主站/真实 UI 用途传递和独立语义攻击评测还要补；不能声称对任意本案问句自动识别已验收。

下一轮继续真实 React UI 与证据契约联调，包括用途/条件、原文、来源状态、缺口和错误展示；随后补历史案例/记忆治理及权限边界、独立保留题集。专用 reranker 模型、正式 hybrid 回填、性能费用预算、部署回滚和专家复核仍按[台账](RAG持续优化执行台账.md)推进，不能勾成完成。
