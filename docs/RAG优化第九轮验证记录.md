# RAG 优化第九轮：断连取消与资源清理

> R07/R09/R15/R16 部分实现；2026-10-22。客户端中断到服务端合成调用的机制已验证；阻塞数据库及时取消、真实外部服务的停算/停费及共享部署仍未验收。

## 实现与审核结论

之前“停止接收”只取消浏览器请求，FastAPI 同步 LangGraph 仍可继续占用线程并发名额、调用模型与检索。本轮补齐传输取消链：

- `/answers`、`/retrievals` 和 SSE 在客户端断开后取消本次请求；LangGraph 在下一步骤、外部调用及结果发布前检查共享取消标志。
- 同步图运行在有界工作线程中。图未退出时不释放并发名额；有界队列不会在断开后无限积压结果。SSE response 的最外层 `finally` 也处理生成器尚未开始就发生的断连/发送错误。
- 模型、Embedding、专用重排和法宝调用采用可取消的异步 HTTP/MCP 会话。在途客户端取消时关闭连接/会话并等待清理，不将取消吞成普通服务失败，不再开始后续来源调用。
- 同步数据库调用不能安全地从另一线程强行杀死。本轮取消后等待已运行 SQL 返回，再阻止下一调用；PostgreSQL 原有 statement timeout 限制其最长运行。等待期间保留并发名额，避免“假释放”导致超额并发。
- 服务端只报告本地客户端/工作线程清理；未证明远端模型供应商已停止执行或停止计费。代理/网关若不传递断连、服务重启和外部会话清理仍需另验。

复审发现旧的同步 HTTP 调用不响应图线程的取消标志。将这几种在途连接改为可关闭的异步上下文管理器，并分别补针对模型静默流、Embedding、rerank、MCP 会话的实际 HTTP/async 清理测试；另测 JSON/SSE 断连、响应发送失败、预算超时、取消后的再入请求与并发名额。没有通过提前释放资源、强杀线程、扩大无界排队或放宽预算实现“取消”。

规划 R09/T09、R15/T15、R16 与目标架构/检索图已补充“检测断开、停止后续工作、连接清理、真实退出后释放资源”层级。当前目标未改变为弱化要求；远端停算/停费仍是独立的完成门槛。

## 余项与下一轮

保留上一轮并发构建导致一项 30 秒超时的记录；顺序运行后全量通过，没有删除或缩小断言。首屏性能/生产并发/可靠性题集仍未测；完整 npm audit 仍因 registry bulk 端点超时未完成。

RAG 同步 PostgreSQL SQL 正在执行时，本轮不做不安全的跨线程连接关闭；依赖 SQL statement timeout，超时之前本轮 worker 和并发名额仍被占用。真实 OpenCode 上游中断后的 session interrupt/资源删除、法宝服务端任务状态与计费均未做专项远端实测。下一步取得隔离测试条件后验证这些供应商/代理边界，再进行真实模型、索引、法宝与工作台业务联调；不接入个人凭证，也不重启共享服务。
