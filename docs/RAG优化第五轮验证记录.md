# RAG 优化第五轮：逐段答复与原文支持核对

> 对应 R08 的部分实现。新增核对不是法律适用性证明，也不是独立模型质量达标；整体目标继续执行。

## 实现

原链路只检查是否出现有效引用编号，无法阻止“金额不一致也可直接放行。[1]”引用一段实际禁止放行的原文。现在在生成之后另行调用 SDK 核对全部展示段落，使用原问题、答复段落和相同的选中原文窗口，不传历史会话作依据。

核验响应逐段给出 supported/unsupported/uncertain、引用编号和精确原文短引。确定性代码要求：每段恰好核对一次；每个引用均有支持；短引必须连续存在于该编号原文；不允许跨源借引、伪造片段、布尔索引或漏项。保存答复/段落 hash、引用内容 hash、短引字符位置；若为长文窗口，同时映射到父片段位置与 hash。位置均按 Unicode codepoint 半开区间。

语义支持仍由模型判断：检查条件、否定、例外、主体、金额币种、时间、司法辖区及法规效力，原文相似不等于支持。精确短引只证明原文存在，不足以证明逻辑蕴含；报告状态刻意命名为 supported_by_model，不叫法律验证通过。复核与生成可能使用同一底层模型，相关错误仍可能发生，后续需独立题集、不同核验模型对比与业务抽检。

核验格式异常、原文不符、缺项、不支持、不确定、超时或上下文超预算时，保留可查看来源，隐藏未获支持的业务答复，grounding=insufficient；纯证据接口跳过生成和核验，不增加无必要调用。没有自动反复修改直到“通过”。默认增加一次实际模型调用，仍受完整请求总预算约束。

回答生成要求每句话带引用，不生成无依据的开场白、标题、通用免责声明或程序建议；服务局限通过既有 warnings 单独显示。当前段落分割基于换行及中英文问号/感叹号/中文句号，英语复合段可能作为整体检查，不宣称原子级语义切分已完成。最多 32 段、答复 10000 字符；单次核验上下文超过 SDK 限制则明确不通过，未静默截断。

## 实际验证与发现

| 验证 | 实际结果 | 限制 |
| --- | --- | --- |
| 全回归与启动 | 110 项：109 通过、1 外部语料路径测试跳过（实际 PostgreSQL 已显式启用）；隔离 uvicorn 与新 OpenAPI 契约通过 | 未完成真实 UI 或业务题集验收 |
| 机制回归 | 覆盖支持原文定位、每段/每引用完整映射、伪造短引、错源、重复索引、uncertain、超时、合法编号但错误结论被隐藏 | Mock 断言检查流程，不证明任意幻觉可检测 |
| 实际 SDK 错误结论对照 | “金额不一致仍可因历史已通过而直接放行”判 unsupported | 单一合成反例，不能推断拒答率或误放率 |
| 实际 SDK 正确结论对照 | 逐字有据的暂停、核对、更正重提表述判 supported_by_model；1 段、1 个精确短引；14.09 秒 | 单一合成正例，不能推断整体准确率 |
| 首次完整生成链路 | 5 段生成答复被核验判 unsupported、隐藏；与错误对照合计 84.55 秒 | **未把安全拒绝包装成答复可用性通过**；已收紧生成要求并复测，结果另列 |

只使用合成原文与问题，实际 SDK 调用已发生，费用须以账单确认。首次完整链路没有保留详细失败段落，因此不能断言是核验误拒还是生成有额外主张；不凭猜测降低核验标准。修订后复测仍未通过（3 段，78.12 秒），已保留合成答复和核验输出到 ignored data。核验支持第一段处理步骤，但拒绝将“历史已通过”扩写为“历史同类单据已通过”，也未接受原文外的来源/适用性说明。这个严格拒绝暴露生成仍有额外主张，不能计为业务答复可用性通过；后续须收紧结构化生成契约、分离确定性服务局限，并评估语义核验误拒，不靠放宽标准通过。不会把业务资料或凭证写入报告。

复现：`python -m unittest tests.test_answer_verification -v`；全回归需显式设置 `HBCN_TEST_POSTGRES=1` 才运行实际隔离数据库用例。`python scripts/smoke-isolated-api.py` 不调用模型，检查服务启动和新响应契约。`python scripts/smoke-answer-verification.py --execute` 使用合成资料调用实际 SDK 正反对照，有费用，不作为默认回归。

## 剩余项

法规适用性仍欠缺业务时点、司法辖区、适用主体及版本冲突的确定性门禁；原文支持模型不能替代这些条件。金额数值保真仍需类型化计算与边界题集。专用 reranker 模型尚未部署，真实 UI、任务权限、历史案例/记忆治理、独立保留集、上线预算与回滚继续推进。详见 [执行台账](RAG持续优化执行台账.md)。
