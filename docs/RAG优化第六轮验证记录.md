# RAG 优化第六轮：结构化答复契约与失败复测

> 对应 R08 的部分修复；承接第五轮完整生成两次被拒。未将单样本通过扩展为质量验收完成。

## 修复方式

自由正文改为严格 AnswerDraft：模型只返回 statements，每条包含一句业务结论和至少一个带来源编号的精确短引 supports。禁止额外字段、多句话夹带、内嵌编号或换行布局；最多 12 条、每条 1000 字符，业务文本合计最多 6000 字符。短引必须存在于对应选中原文窗口，服务端生成引用编号并渲染正文，服务局限和来源状态继续由 warnings 等字段单列。

该契约允许忠实概括和跨来源支持，**不强制把所有回答退化成复制原文**。但不得新增原文没有的主体、金额币种、时间、条件或流程；如无需概括则优先保持准确表述。JSON schema/精确短引只管结构与原文存在性；仍使用第五轮独立调用的逐段语义支持检查，不能拿一处原文里的“暂停处理”来支持“允许放行”。模型不足或核验失败仍隐藏答复，不以降门槛获取通过。

生成超时与草稿格式错误分开记录为 generation_unavailable / invalid_draft；保留来源，不把上游中断伪装成“没有资料”。纯证据入口保持跳过生成及核验；没有给每次请求添加无限修复循环。

## 实际结果

| 验证 | 结果 | 边界 |
| --- | --- | --- |
| 最终回归与启动 | 115 项：114 通过、1 外部语料路径检查跳过；实际 PostgreSQL 隔离测试已启用；隔离服务启动及 OpenAPI 通过 | 不等于业务质量题集或共享部署验收 |
| 结构/反例回归 | 原文短引、非法编号/布尔索引、伪造引用、多句/换行、额外免责声明字段被拒；反向结论即使带有效原文短引仍由语义核验拒绝 | Mock 验证控制与失败机制，不代表任意幻觉均能捕获 |
| 生成失败回归 | 保留来源，generation_unavailable，grounding=insufficient | 未证明真实服务所有故障模式 |
| 实际 SDK 完整链路 | 规划→合成证据覆盖→结构化生成→逐段复核，grounding=cited，supported_by_model，2 段，1 来源，包含更正要求 | 合成检索引擎、实际 SDK；没有调用真实数据库或 MCP，不证明召回/法规适用性 |

本次烟测使用与第五轮相同的合成规则：金额不一致须暂停、核对、更正重提，不得仅因历史已通过而直接放行。与第五轮两次生成后被拒相比，本次通过说明结构化契约对**这个失败样例**有效；未证明整体误拒率改善，也未降低所需规划、检索和法效质量门槛。旧失败记录仍保留，不能用本轮通过覆盖历史结果。

## 复现与后续

运行 `python -m unittest tests.test_answer_draft tests.test_answer_verification -v`；实际模型链路为 `python scripts/smoke-structured-answer.py --execute`，只用合成材料、不连数据库/MCP，会产生 SDK 调用费用，非默认回归。脚本保存无凭证、无原文的 ignored 摘要，失败以非零退出，不预填通过。
