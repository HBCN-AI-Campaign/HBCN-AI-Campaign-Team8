# RAG 优化第十一轮：真实检索排名采集入口与评测复审

> R04/R06/R10/R16 部分实现；2026-10-22。采集入口已实现并经合成依赖测试，尚未运行真实金标题集或专用重排模型质量评测。

## 实现与复审修复

第十轮只有比较排名文件的工具，没有从检索实现生成成对排名的入口。本轮增加 `scripts/run-retrieval-evaluation.py` 与 `app/evaluation_runner.py`：调用现有 PostgreSQL 引擎、查询族 RRF、跨源 RRF 和专用重排适配器。按题使用专家事先审核的固定查询表达，每题一次采集共用候选池，生成基线、候选及报告三个文件。不会调用查询规划/答复 LLM；不能因此声称整个 Agentic 链已经评测。

复审发现并修复的边界：

1. 采集器保留完整最多 20 条候选及两种完整排名；Recall@20 与 nDCG@10 各自按 K 计算，不能把只保存 10 条的结果称为 Recall@20。
2. 基线/候选绑定同一 comparison ID、候选 ID 集和内容摘要；摘要由文件内容重新计算，重复、丢失或替换候选不能通过契约。`ev1:` ID 对来源、版本、片段和正文哈希再作 SHA-256，结果文件不带正文、查询或来源路径；仍可暴露资料成员关系，须存于受控环境。
3. 每题 schema 增加实际 scope、来源与固定查询表达，第一条必须保留原始问题。外部来源沿用 law/all 范围约束，未配置来源/重排器、超过预算或外部结果不完整即中止，不伪装出有效候选对照。
4. 按案件泄漏组重采样，再计算逐题加权的配对差值置信区间；同案多问不视为独立样本。独立组不足 2 时不输出区间，另报题目数和独立组数。排序指标算例不证明真实增益。
5. 在初始化真实引擎前检查数据、输出路径、模型/来源及调用范围。独立参数分别确认向远程 Embedding 发送问题、向远程 reranker 发送片段，以及调用法宝；不修改既有服务配置。默认最多 120 题、最高 500 题，每题至多既定查询预算。`--max-external-calls` 计来源查询次数，每次法宝适配可能执行 1 次搜索及最多 2 次补条文工具调用，报告给出工具调用上界。
6. 命令行直接执行时补充模块搜索路径；两个 CLI 的 `--help` 已实际执行。旧的 runpy 单测不能单独证明新进程里的脚本可启动。
7. 同一最多 20 条候选池中，重排的 Recall@20 恒定；报告写明其只描述覆盖，排序变化看 nDCG@10，召回收益另做检索策略实验。案件组测试使用题数不等且效果相反的组，核验逐题均值及整组采样；当前为 percentile 区间，不是 BCa，独立组少时不能解释为可靠质量结论。
8. 两个 CLI 对非法题集/排名输出经过清理的错误，避免 Pydantic 异常链把查询或业务输入打印到终端；新增无正文泄漏、无输出文件的失败用例。这不替代应用全链路日志审计。

输出使用 exclusive create，不覆盖既有文件；写入失败清理本次新建的输出。未实现签名、持久审计或不可变快照证明，不能拿文件摘要代替这些能力。

## 未完成范围

当前采集用冻结查询表达控制排序实验变量，尚不能评测模型改写正确性、多轮补查、最终答复支持/拒答/法律适用或任务 ACL；这些继续按 R01–R17 的独立门槛验收。内部案例/经验记忆、网页来源、正式混合索引迁移、真实 reranker 模型选型与部署、资源费用锁定和真实业务 UI/部署均未因此完成。

报告不能证明语料快照不可变、候选映射的专家标注准确或远端权限合规。下一步需要受控题集、模型资源和匹配的索引快照执行基准；其余不依赖这些资源的案例/记忆及权限代码仍可继续推进。
