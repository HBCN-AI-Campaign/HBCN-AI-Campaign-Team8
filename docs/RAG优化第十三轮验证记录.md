# RAG 第十三轮：文档撤回、在途发布屏障与答复复核

> 2026-10-22；R09/R12/R15/R16/R17 部分实现，服务 0.3.1 / 契约 1.1.0。上一轮独立模块交付已完成，本轮不将当前服务限制当作目标上限。

## 审核发现与实现

部署复审发现，启动会全局恢复入库任务，多实例仍缺所有权/持久队列；不能通过增加 worker 解决。继续核对生命周期时发现更直接的缺口：普通知识文档没有撤回入口，原文接口未检查撤回，Agent 跨轮持有片段也没有失效复核。本轮先落实此项 T12/T15，队列/租约仍是明确待办，没有提高 worker 数或声称已支持多实例。

新增 `POST /api/v1/documents/{id}/withdraw` 与 React 二次确认。请求携带内容 hash 与枚举原因，禁止客户端自报管理者身份；服务 Token 仍只是可信调用方，主站必须自行实现最终用户的管理权限和操作审计。未知文档 404、版本不匹配 409、重复撤回幂等；文档状态/hash 是新增字段。

撤回事务锁定文档行，原子更新 withdrawn、事件和所有片段的 searchable 标记，向量和词法共同使用该标记。原文/content 接口拒读，管理元数据仍可查。撤回不可被 retry、重复同内容上传或在途入库最终发布覆盖。最后发布事务使用同一文档行锁；依据 PostgreSQL 官方的[行锁语义](https://www.postgresql.org/docs/current/explicit-locking.html)，并通过实际数据库并发屏障验证，不凭测试 Mock 断言事务正确。

普通检索返回后、跨轮融合候选、后续模型调用前和最终答复返回前重新核对本库 document/chunk/model/state。失效候选被移除；生成过程中撤回则隐藏原答复，不沿用充分性、法律适用性或引用编号。API 全部设置 no-store；外部法宝生命周期由其来源适配负责，不把本库检查扩大解释为外部授权已验证。

总览当前架构及[撤回流程图](diagrams/rag-document-withdrawal.mmd)已同步。原件、正文和不可检索片段保留；本轮没有物理擦除、跨库案例来源绑定、备份清理或跨系统撤回通知。不能召回调用方已收到的正文，也不能强停已发往外部供应商的请求；最终复核到网络发送间仍有竞态，因此不宣称线性一致的实时撤销。调用方不能把旧结果长久缓存后继续作为当前依据。

## 验证与复审

专项使用随机 `rag_lifecycle_test_*` schema 和临时合成原件；不迁移正式索引、不导入真实业务文件、不调用模型/Embedding。真实 DB 测试包括：

1. 正常入库能够 ready 和混合检索，再撤回停止召回，防止只验证拒绝路径。
2. hash 冲突、服务鉴权、自报 actor、幂等、原文拒读、向量提供方返回旧结果、词法状态、重复上传及 retry 均验证。
3. 入库线程在 indexing 阶段暂停，撤回提交后恢复线程，验证不能再次发布 ready。
4. 生成模型处理中撤回，实际图最终不返回原文和原答复；证据接口在覆盖评估后撤回也不能声明 sufficient。
5. UI 自动测试要求先弹确认框再发请求；实际浏览器通过 Cookie/FastAPI 执行上传、轮询和撤回状态展示。浏览器依赖为合成，无真实模型/数据库/MCP 联调。
