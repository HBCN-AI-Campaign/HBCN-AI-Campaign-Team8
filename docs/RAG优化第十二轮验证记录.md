# RAG 第十二轮：独立模块交付与案例/经验治理

> 2026-10-22；R09/R11/R12/R15/R16/R17 部分实现。用户要求固定模块接口，提交可协作版本，由汇丰云部署同事接手资源与环境；不因现有机器降低目标质量。

## 实现与复审

独立模块维持 `code/rag-service`；对外保留旧 `/query`，以 `/retrievals` 提供增强证据检索，独立问答才生成答复。新增服务版本 0.3.0、契约 1.0.0、响应头、OpenAPI 快照/漂移检查、HTTP 消费示例、[接口契约](../code/rag-service/API_CONTRACT.md)和[云部署交接](../code/rag-service/deploy/README.md)。其他模块不需要导入 RAG 类或读内部表，后续模型/资源替换通过模块内适配完成。

原生 Linux/systemd 与多阶段 Dockerfile 提供部署起点；不捆绑数据库、模型或真实资料。模板不设置压低质量的机器资源上限；算力/专用模型可外置 API。当前单 worker 是入库恢复没有租约的代码约束，横向扩展仍需持久任务所有权，不把增加进程数当作部署优化。当前机器没有 Docker，未完成镜像构建或汇丰 ECS 部署。

案例/经验实现独立表、API 和治理主体权限：范围/角色/期限服务端绑定，作者不能自批；不可变正文版本、内容摘要与状态 revision；条件过滤后 PostgreSQL FTS/GIN；至少两个不同案例的经验来源、源版本绑定和期限约束；发布/撤销/版本替换在同事务传播；过期禁止读取、清空正文/索引文本；不含正文的写入/读取审计。接口默认关闭，未自动导入业务文件，尚未接入 Agent 或主站用户/任务 ACL。详见[治理契约](RAG案例与经验治理契约.md)。

复审与修复：

1. 删除重复继承执行的测试，专项保留 10 个有独立目的的测试。
2. 实际 PG 检查发现函数表达式索引未自动附着到表，导致最初测试“检索成功”没有证明 GIN 存在；显式绑定表并增加真实索引存在断言后复测通过。
3. 发布与撤销并发通过事务行锁协调；实际 PG 两线程验证源撤回后没有可读取的派生经验。
4. 过滤失效父来源和评测排除组在 SQL 侧完成，再做原文读取核查；不是返回候选后才做权限过滤。排除集仍由可信评测管理者提供，不宣称自动防止所有泄漏。
5. 到期清理重读当前状态，避免同一事务中派生版本被重复清理而回退 revision；计数包含实际清除的派生记录。
6. 服务身份中间件改为原生 ASGI 包装，避免改变断开/取消和 SSE receive 语义；完整取消回归继续通过。
7. 旧检索/上传接口不再向外透传第三方异常正文；保留状态码/detail 形状，新增兼容与异常脱敏测试。
8. 浏览器烟测默认 Python 路径按 Windows/Linux 选择；测试 PDF 生成依赖补充到 requirements-dev，运行依赖不加入纯测试库。
9. 未构建 React UI 时返回明确的 503 页面，不再回退到旧静态演示页，避免部署遗漏被错误界面掩盖。
