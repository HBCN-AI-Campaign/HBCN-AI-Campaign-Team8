# 第十八轮：主站增强证据契约与澄清信息保留

2026-10-22；基线提交 `1e42795`；范围 R09/R15/R17 的消费侧接口和对应图文。本轮继续执行 v3 规划，未调整任何业务质量门槛。

## 审查发现与修复

上一轮主站已调用 `/retrievals`，但只把充分性降为泛化告警，具体 missing、clarification_question、停止原因和来源状态没有传给最终答复模型。响应字段也未按类型校验，未知状态或结构错误可能被当作正常候选处理。

- 主站用已有 Pydantic 验证消费字段：原文、充分性、轮次与停止原因；接受 v1 新增字段，拒绝未知/缺失充分性、非列表缺口/来源、错误来源字段和布尔轮次。`sufficient` 却没有非空原文同样拒绝，不以 HTTP 200 代替有效证据。
- 校验失败只抛通用错误，不把包含原文或私有输入的 ValidationError 透出。现有服务失败路径保留任务本地证据并记录共享知识不可用。
- 适配器保留原文与缺口、澄清、来源、重排、上下文覆盖和法规诊断。主站将限长后的具体缺口/澄清/来源与重排状态/停止原因/轮次传入本次 runtime 指令的数据区，并声明文本不是指令或本案事实。
- 模型策略明确：需澄清时优先补问；未连接/调用失败不能声称已取得共享知识；参考资料充分不意味着本案法规适用或贷款审批通过。不足或失败时仍提供概括执行提示，不透出底层异常。
- 更新总览当前实现图、独立主站接线图、R17 规划、接口与部署说明。主站只显式选择 `knowledge_base` / `purpose=reference`，本轮没有接通法宝、网页或任务资料入库。

## 未完成项与下一轮

这是服务契约与主站消费路径的合成验证，没有调用真实 RAG 索引、汇丰模型、法宝或网页上游，未完成独立金标、法规业务质量或模型遵循率验收。主站原文代理/引用定位、会话语境下检索、主站断开到 RAG 的取消传播、真实 UI/云端凭证与代理超时仍须逐项推进。检索状态限长可能截取说明文本，不能声称模型看到了完整来源诊断；不得把这类摘要当作完整法规审查。

主站原有最终答复没有自动复用 RAG 独立问答的逐结论核验，因此本轮也不宣称主站答案已通过该质量门禁。独立题集、专用 reranker 实测、知识生命周期/案例依赖完整传播与发布回滚仍按原规划保持未完成。
