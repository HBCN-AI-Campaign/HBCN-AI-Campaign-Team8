# RAG 第十四轮：入库质量隔离、版本绑定复核与旧库重检

> 2026-10-22；R12/T12、R09/T09、R15/T15、R16/T16 部分实现。服务 0.4.0 / HTTP 契约 1.2.0；完整目标继续执行，不因本轮回归通过而结项。

## 复审发现与修订

原入库将“能够提取非空文本”视作可索引，缺少乱码/空单元门禁；OCR 截断、旧编码、DOCX 段落表格顺序及 Excel 缺缓存公式可能污染依据。本轮增加版本化机械报告及待原文复核状态，复核绑定原件/解析/报告三份摘要和服务端主体，不相信客户端自报人名。批准复用已核对正文而非重新 OCR；无效字符不能人工绕过。机制与部署步骤见[质量契约](RAG文档质量门禁契约.md)。

复审进一步发现旧索引缺解析来源记录，不能默认为通过。现在知识库检索及图的输出前检查当前质量策略，旧 ready 缺报告默认排除；新增独立凭证授权重检和只读清点工具，就绪接口暴露迁移缺口。本机只读事务清点为 ready=10、failed=1，10 份 ready 均待重检。没有对正式表 DDL、重检、审批、Embedding、索引切换或共享服务重启。

API 已更新 OpenAPI；旧消费者须正确处理 quality_review/quarantined 和未知状态，不把 202 当完成。三个新增质量接口要求独立 reviewer 凭证；普通工作台仅展示待复核/隔离提示，没有内置审批凭证。总览、规划与[质量流程图](diagrams/rag-document-quality.mmd)同步，旧架构图仍保留已验能力和未完成边界。

## 剩余工作和下一轮

机械检查不是 OCR/金额准确率或完整性证明。真实扫描/跨页表格/漏页/复杂版面金标、成熟解析方案比较、来源授权、文档版本/政策时态、完整派生依赖与备份擦除仍未完成。人工逐单元声明也不能证明实际看过原件。审批被拒不能仅重试后忽略缺失内容，应更正并按受控流程再审。

旧库迁移前召回可能受未验证旧候选占位影响，不能发布质量合格结论；请在隔离副本完成重检、必要复核和回归。R09 主站用户/任务 ACL，R11 案例/Agent 接线，真实金标排序/答复质量，R15 持久队列/任务所有权，R16 云端运行/负载/回滚继续列为待办。没有 Docker/云运行证据，不降低目标来迁就当前资源。
