# RAG 优化第十轮：检索质量评测契约

> R16 基础设施部分实现；2026-10-22。评测方法已可复现，真实质量验收尚未开始。

## 变更与复审

新增严格评测集契约：固定六组、版本/规划基线、案例唯一 ID、不透明的泄漏分组 ID、语言、回答可用性、逐证据 0–3 级相关性、预期处理方式、来源快照及逐题审核标志。Holdout 每组至少 20 题；可回答样本须有正相关证据，无答案样本不得有正相关标记。开发集/保留集可运行隔离检查，拒绝案例 ID 或案件分组交叉。

新增排序对照 CLI：针对同一题集版本、同一组 case ID 的 baseline 与 candidate，计算 Recall@20、nDCG@10、按组分层指标、逐题配对差值及确定随机种子的 95% bootstrap 区间；报告带 SHA-256 摘要。排名输入只保留不透明 evidence ID，不需要复制单据或证据正文。no_answer 题不混进排名分母；这些题的拒答质量仍需另一套标注和指标。

复审边界：Pydantic 标志只是数据契约，不是审核者身份认证；CLI 不能保护本地 JSON。真实保留集必须放在授权、可审计、受控且可管理签名/版本/解封权限的存储。本轮没有产生题目或真实标签。

## 验证证据

| 检查 | 实际结果 | 范围 |
| --- | --- | --- |
| 评测器单元测试 | 7 项通过 | holdout 六组最低数量、未审核/重复/冲突金标拒绝、案例跨集污染、指标算术、bootstrap 可重现、CLI 强制开发集与数据集版本/case coverage |
| 完整 RAG 后端回归 | 145 项：144 通过、1 外部真实语料路径检查跳过 | 显式启用实际 PostgreSQL 隔离测试；合成机制回归不代表检索/答案质量 |
| 真实题集/模型/索引 | 未运行 | 尚无经授权的业务金标与真实保留集，不填造结果 |
| 评测报告完整性 | 输出 SHA-256 可重复 | 不代表来源数据可信、权限受控或签名有效 |

详细数据契约及复现命令见[评测目录](../code/rag-service/evaluation/README.md)。从 `code/rag-service` 运行 `python -m unittest discover -s tests -p test_evaluation.py -v` 检查评测器；设置 `HBCN_TEST_POSTGRES=1` 后运行 `python -m unittest discover -s tests -q` 覆盖完整回归和隔离 PostgreSQL 测试。

## 下一步
