# RAG 优化第四轮：长文原文窗口与联合覆盖

> 对应 R07/R08/R12/R17 部分实现。修复 SDK 静默截断风险，仍未完成法规适用性、逐结论引用支持、独立题集及端到端发布验收。

## 问题与实现

现有 OpenCode runtime 源码约定：最多 20 条 evidence、每条 4000 个 JavaScript UTF-16 单位、会话 12 条/每条 4000 单位、请求体 256000 字节。原 RAG 客户端只取 Python `content[:4000]`，会丢失长文尾部；emoji 又可能在 runtime 端再次截断。20 段中文加长会话也会超字节预算。这些不是扩大模型上下文就会自动解决的服务契约限制。

新增 evidence_context，复用 LangChain RecursiveCharacterTextSplitter 建立精确原文窗口，保留重叠上下文；按 UTF-16 单位约束适配 SDK。每个长片段窗口保存 parent_chunk_id、原文 hash、起止字符、原文长度、窗口序号/总数和切分方式，保留原片段链接及页码；内容是原文切片，不由模型摘要替代。重复内容导致上游定位歧义时回退到确定性字符窗口，仍检查范围覆盖。偏移使用 Unicode codepoint 半开区间，前端 JS 不能直接把它当 UTF-16 下标。

按候选轮流纳入窗口，避免首个长来源耗尽预算；默认最多 80 窗口、6 批，每批最多 20 条，按与 httpx 一致的 UTF-8 JSON 字节编码核对 220000 字节批次预算。SDK 客户端再检查 250000 字节余量，任何越界都显式失败，不截正文、不静默丢会话。API 拒绝会被 runtime 丢弃的超 UTF-16 会话。

每批用原文筛选支持、限制和反例；多批选中后再对保留的原文做一次联合覆盖检查，不把各批分别“有关联”当成整体充分。初筛缺口作为不可信核查清单传给联合检查，不代替事实。联合原文仍超过单批、窗口/批数预算耗尽或中途失败时，保留部分支持证据并明确缺口，不能标为充分。总时间预算仍约束所有调用；最多 6 次初筛及 1 次联合核对，实际不保证预算内能全部完成。

响应新增 context_coverage，包含 candidate_windows、presented_windows、batch_count、input_complete、selection_checked。这里 input_complete 只表示本轮入围候选窗口已完整提交给模型，不代表读完整个知识库/整部法规、不证明模型注意到每句话或法律适用性正确。充分性仍需真实质量评测及人工抽检。

## 验证结果

| 验证 | 实际结果 | 边界 |
| --- | --- | --- |
| 显式 `HBCN_TEST_POSTGRES=1` 后全回归 | 100 项：99 通过，1 外部真实语料路径检查跳过 | 包含实际 PostgreSQL 隔离测试；不等于全部生产语料验收 |
| 长文精确位置/覆盖 | 重复段落、尾部例外、原文 hash、窗口串接无漏空通过 | 窗口定位是片段字符位置，不生成虚假 PDF 页码 |
| UTF-16/字节边界 | emoji、20 段中文＋长会话分批、与 httpx 实际编码长度一致、超限发网前拒绝通过 | 不改变主 runtime 限制 |
| 分批联合覆盖 | 21 条候选跨批筛选后使用原文联合检查；冲突与初筛缺口保留通过 | Mock 断言机制，不证明任意冲突均识别正确 |
| 生成与引用一致 | 回归确认生成阶段读取的选中窗口与返回来源内容完全一致 | 引用编号有效仍不证明每条结论都受原文支持 |
| 不完整输入 | 窗口预算耗尽、中途调用失败保留部分依据且不充分通过 | 无无限补检索或无限模型调用 |
| 真实 SDK 长文烟测 | 14378 字符合成材料→6 窗口，完整提交 1 批；返回 1 个含末尾关键限制的窗口，带精确位置；约 31.23 秒 | 使用合成检索引擎及真实 SDK；不是数据库召回测试，也不是业务法规金标 |

真实问题：“合成测试规定里，支付指令金额不一致时应如何处理？”关键合成条文在 14000 字符之后，规定暂停、核对、更正后重提，并禁止仅因历史通过而放行。真实模型返回的来源窗口包含该末尾限制。纯证据入口没有生成业务答案；已产生 SDK 调用，费用未由烟测估算。仅保存无正文/凭证的 ignored 验收摘要。

## 复审与剩余项

复审补上三个容易误报的地方：Python 长度与 JS 长度不同；按条数限制仍可能超请求字节；分别有相关片段不等于联合证据覆盖。引用返回实际窗口而不是未提交的整段正文，避免让用户误以为模型看过更多内容。窗口元数据中父片段 rerank 分明确标为 parent_excerpt，不能当该窗口独立重排结果。

未解决项：专用 reranker 的模型 token 截断仍未核验；法规辖区/主体/业务时点与效力缺少确定性适用性门禁；引用仍主要检查编号，尚未逐结论核对原文支持；跨批筛选存在模型遗漏反例风险，需独立题集及业务抽检。真实 UI 的精确窗口高亮、历史案例/记忆治理、任务权限、部署灰度/回滚继续实施。

复现：在 RAG 虚拟环境运行 `python -m unittest tests.test_evidence_context -v`；全回归 `python -m unittest discover -s tests -q`。实际 PostgreSQL 需显式设置 HBCN_TEST_POSTGRES=1；启动契约验证 `python scripts/smoke-isolated-api.py` 不调用模型或初始化共享数据库。真实长文烟测为 `python scripts/smoke-long-context.py --execute`，使用合成资料和真实 SDK，会产生模型调用，不作为默认回归自动执行。范围与代码以 [持续执行台账](RAG持续优化执行台账.md) 为准。
