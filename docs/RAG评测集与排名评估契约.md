# RAG 评测集与排名评估契约

> R16 的评测基础设施；2026-10-22。评测器和数据格式已实现，真实独立金标集没有创建，质量门槛尚未实测。

## 已实施

`code/rag-service/app/evaluation.py` 提供严格 Pydantic 数据契约。六个组别固定为基础、跨语言、多源法规、历史案例、无答案/冲突、权限攻击。每个 holdout 组至少 20 条经审核样本；样本包含稳定不透明的泄漏分组 ID，以便开发集/保留集按案件/案例分组去重。无答案样本不得将任何证据标为相关；可回答样本必须至少有一条相关证据。未审核样本、重复 evidence ID、未知字段及不一致数据集版本都会被拒绝。

`scripts/evaluate-retrieval-quality.py` 在相同题集、相同数据版本上比较两份排序列表，逐题计算 Recall@20、nDCG@10，并给总体和组别的配对差值及确定种子的 95% bootstrap 区间。holdout 运行强制提供 development set 并检查案件分组不交叉。输入仅包含不透明 evidence ID，不要求把业务原文复制进结果文件；输出报告带 SHA-256 摘要。排名结果需由匹配标注所引用的同一索引快照产生；CLI 只校验文件契约，不能自行证明来源快照。

第十一轮增加 `scripts/run-retrieval-evaluation.py` 真实检索采集入口：使用标注集内审核冻结的原始/泛化/翻译查询，经现有 PostgreSQL 检索与 RRF 后，对同一候选集运行已配置的专用重排，输出成对排名与报告。保留完整最多 20 条，按 K 分别计算指标，案件组 bootstrap 区间不足 2 个独立组时不输出。严格校验 comparison ID、候选 ID 集和其内容摘要。远程 Embedding、重排、法宝数据流分别显式配置，初始化真实引擎前执行预检；来源失败或候选改变中止比较。该入口尚未使用真实金标/专用模型运行，见[第十一轮记录](RAG优化第十一轮验证记录.md)。

数据字段、命令、指标范围与保存边界见 [评测目录说明](../code/rag-service/evaluation/README.md)。该执行器只评检索排序；不评答复正确性、拒答、ACL、法律适用性或成本/延迟，排名指标不能单独通过规划门槛。

同一最多 20 条候选池的重排不会改变 Recall@20；此处该指标只描述候选覆盖，重排收益看 nDCG@10。检索改写、通道或多源召回的提升需另做允许候选集变化的检索实验，不能套用本执行器声称提升。未标注证据按零相关处理，正式评分前须复核标注覆盖。区间为 2,000 次按案件组配对的 percentile bootstrap，非 BCa；两组只足以计算，不能据此宣称可靠收益或替代样本量分析。配对重采样的通用原则参考 [SciPy 官方说明](https://docs.scipy.org/doc/scipy/reference/generated/scipy.stats.bootstrap.html)，案件组采样是本项目的适配实现。

## 复审限制与待办

本轮测试数据均为代码内合成合同夹具，只验证契约和指标算术；没有制造 120 道题、真实问题、法条标签或审核案例。布尔审核标志不是身份认证，当前工具也不提供受控存储、签名、审计或 holdout 解封管理；真实题集须由授权评审流程管理，不能把未保护的本地 JSON 当保留集。

评测题集真实建成前仍需：授权业务专家为六组逐题复核预期证据/处理方式；按案件与来源版本切分并检查 leakage group 不交叉；用固定索引和版本运行基线/候选；另行人工抽查答复支持、引用锚点和法规适用性；量测延迟、调用数与费用；冻结报告阈值并保存可复现环境。全部按 [优化规划门槛](Agentic-RAG优化规划.md) 执行，不因当前指标可计算而降低要求。
