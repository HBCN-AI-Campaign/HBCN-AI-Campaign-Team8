> 写给下一个接手的人（尤其做 RAG 的 Codex 会话）。本文记录：现状、关键决策、踩过的坑、用户各轮需求演进，以及续作建议。
> 更新时间：2026-10-19

## 1. 一句话现状

AI 助手（`/api/assistant` + 前端 `/assistant`「慧眼助手」页）**主体已可用并通过构建与测试**：
- 后端：FastAPI 路由 + OpenAI Agents SDK 封装 + SSE 流式 + 会话/消息持久化 + 权限隔离。
- 前端：Vue 3 三栏界面（会话栏 / 对话区 / 审核技能栏），流式渲染、Markdown（含表格/引用）、步骤时间线、证据引用、一键复制、业务技能商店。
- **RAG 尚未真正接通**（由另一个会话接入中），当前 `rag_available=False`，检索回退到「任务已入库的规则结果 + 单据字段」本地证据。

## 2. 文件清单与职责

后端（`code/backend/app/`）：
- `assistant_service.py`：Agent SDK 适配、受控工具 `search_knowledge_base`、SSE 事件编排、本地演示降级、`_strip_tool_echo()`（见坑 2）。
- `assistant_schemas.py`：会话/消息/能力的通信契约 DTO。
- `routers/assistant.py`：5 个 `/api/assistant/*` 接口，JWT + 用户级隔离 + 任务级权限。
- `models.py`：`assistant_sessions` / `assistant_messages` 表。
- `config.py`：`AI_BASE_URL / AI_API_KEY / AI_MODEL / AI_REQUEST_TIMEOUT`（注意：**尚无 `RAG_BASE_URL`**）。
- `tests/test_assistant_api.py`：4 个测试（会话隐私、任务权限、流式+持久化、JSON 回显剥离）。

前端（`code/frontend/src/`）：
- `assistant/api.ts`：`/api/assistant` 请求 + SSE 解析。
- `assistant/types.ts`：会话/消息/引用/技能等契约。
- `assistant/markdown.ts`：**零依赖** Markdown 子集渲染（先转义后替换，XSS 安全；支持标题/段落/列表/表格/引用/代码/链接）。
- `views/AssistantView.vue`：三栏界面 + 技能商店 + 流式状态机。
- `router/index.ts`、`layouts/MainLayout.vue`：`/assistant` 入口与顶栏「慧眼助手」。

文档：`docs/ai-assistant/README.md`（接口契约、SSE 事件表、时序图、CCSwitch 配置）。

## 3. 关键决策与原因

1. **不引入第三方 Markdown 库，手写零依赖子集**（`markdown.ts`）。原因：本机沙箱一度没有 Node.js，无法 `npm install` 新依赖并验证构建；且助手输出只用到列表/加粗/行内代码/表格/引用这些子集，手写 100 行即可，规避依赖风险。成熟方案（snarkdown/marked）的「先转义后替换」思路已照搬。
2. **不换栈到 React + assistant-ui**。原因：全仓是 Vue 3 + Element Plus，换 React 成本大且与团队协作冲突；Vue 生态无 assistant-ui 级库，故「保持 Vue + 吸收成熟交互细节」。
3. **右栏从「服务状态/LIVE TRACE」改为「审核技能」商店**。原因：用户明确要求去掉服务状态等装饰、要业务向的 skill；技能取自 AGENTS.md 中专项审核 Agent 的能力项（节假日/汇率/提单验真/制裁名单/法规检索），外加「单据比对」。每个技能点击后发送结构化 prompt，要求模型以 Markdown 表格输出。
4. **步骤时间线/工具检索轨迹**：后端只发 4 个固定 step（理解请求/加载业务上下文/检索证据/组织建议），`tool` 事件单独发；前端在流式消息内把 `tool` 渲染成「检索证据 运行中/已完成 N 条」。

## 4. 踩过的坑（重要，供后续参考）

1. **本机沙箱没有 Node.js/npm**，无法 `npm run build`。解决：下载便携版 Node（`node-v20.18.1-win-x64.zip`）解压到 `C:\Users\28462\AppData\Local\Temp\node20\`，用其中的 `node.exe`/`npm.cmd` 跑构建。该目录在系统临时目录，可能被清理；后续需要构建时可用系统 Node 或重新下载。
2. **模型 tool-call JSON 回显 bug（已修）**：经 CCSwitch 的 `gpt-6.1-sol` 在真正调用 `search_knowledge_base` 工具**之前**，会把工具参数 `{"query":"..."}` 当作普通文本 delta 输出，拼进 `answer` 导致正文开头出现原始 JSON。修复：`assistant_service._strip_tool_echo()` 用 `json.JSONDecoder().raw_decode` 剥离前导的工具参数 JSON（仅当含 query/question/input 等键、且剥离后仍有正文时才删）。已加单测，并用真实模型 SSE 复测确认。
3. **openai-agents 0.4.2 与 openai>=2.45 不兼容**（上一会话发现）：新版 openai 的 usage 字段让 Agents SDK 初始化失败。已锁定 `openai==2.44.0`（`requirements.txt` 有注释）。
4. **我临时写的 Python SSE 预览代理会缓冲整个响应**（`urllib.request.urlopen`），导致浏览器里流式不渐进。这是预览代理的局限，**不是应用 bug**；真实 Vite dev server 的 `/api` 代理能正常流式。验证 SSE 应直接打后端 8000 端口。
5. **流式时整个页面被拉长（已修）**：根因是页面用 `min-height` 而非固定 `height`，消息增长把整个 main 撑高。修复：`.assistant-page { height: calc(100vh - 60px); overflow: hidden }`，`.chat-column/.message-list` 用 `flex:1; min-height:0; overflow-y:auto`，`.composer-wrap { flex: 0 0 auto }`。已实测 `document.scrollHeight == window.innerHeight`、composer 贴底不动，只有消息区内部滚动。
6. **RAG 未接线（待另一个会话完成）**：`app/rag_service.py` 之前不存在、`config.py` 无 `RAG_BASE_URL`，`assistant_service._rag_search()` 里 `from .rag_service import RAGClient` 总是 ImportError 而回退本地证据。前端 `capabilities.rag_available` 由 `settings.RAG_BASE_URL` 决定，接上后会自动从「本地证据检索」变成「知识库已连接」。
7. **已知小问题（未改）**：`tool` 检索轨迹只在流式消息内显示；打开历史会话时不会重现（因为 tool 事件未持久化，只有 4 个 step 入库）。若要历史也能看检索轨迹，需把 tool 事件一并持久化。

## 6. GitHub 成熟方案调研结论

| 项目 | Stars | 技术栈 | 可借鉴 |
|------|-------|--------|--------|
| assistant-ui/assistant-ui | 12.6k | React+TS | 最成熟的 AI Chat 组件库：流式、工具面板、Markdown、停止生成 |
| ChatGPTNextWeb/NextChat | 88.9k | React/Next | 会话管理、流式渲染、复制/重新生成 |
| open-webui/open-webui | 156k | Svelte/Python | RAG、工具、多模型、知识库管理 |
| lobehub/lobe-chat | ~60k | React/Next | 函数调用可视化、插件市场 |
| vercel/ai-chatbot | ~10k | Next.js + AI SDK | 官方流式 chat 模板、Markdown + 工具渲染最佳实践 |

结论：Vue 生态无 assistant-ui 级库；保持 Vue + 吸收交互细节（Markdown、工具轨迹、复制、技能卡片），不换栈。
