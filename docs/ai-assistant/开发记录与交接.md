> 写给下一个接手的人（尤其做 RAG 的 Codex 会话）。本文记录：现状、关键决策、踩过的坑、用户各轮需求演进，以及续作建议。
> 更新时间：2026-10-19

## 1. 一句话现状

AI 助手（`/api/assistant` + 前端 `/assistant`「慧眼助手」页）主体可用，并已完成一次面向对话体验与输出安全的续作。**最新改动、验证和剩余风险见第 9 节**；以下前 8 节部分记录是此前开发时的状态，遇到不一致时以第 9 节和当前代码为准。

- 后端：FastAPI 路由 + OpenAI Agents SDK 封装 + SSE 流式 + 会话/消息持久化 + 权限隔离。
- 前端：Vue 3 三栏界面（会话栏 / 对话区 / 审核技能栏），CopilotKit Vue 消息渲染、执行活动折叠、证据引用、一键复制、业务技能商店。
- **RAG 服务由另一个会话负责接入**；助手只通过受控 RAG tool/client 边界调用，不负责维护知识库服务。`rag_available` 和当前部署连通性以当前分支配置及服务状态为准，不要把本交接文档早期记录的状态当作现状。

## 2. 文件清单与职责

后端（`code/backend/app/`）：
- `assistant_service.py`：Agent SDK 适配、受控工具 `search_knowledge_base`、SSE 事件编排、本地演示降级、`_strip_tool_echo()`、`_safe_final_answer()`（见第 9 节）。
- `assistant_schemas.py`：会话/消息/能力的通信契约 DTO。
- `routers/assistant.py`：`/api/assistant/*` 接口，JWT + 用户级隔离 + 任务级权限；历史答复使用 `_message_out()` 做输出安全检查。
- `models.py`：`assistant_sessions` / `assistant_messages` 表。
- `config.py`：`AI_BASE_URL / AI_API_KEY / AI_MODEL / AI_REQUEST_TIMEOUT`（注意：**尚无 `RAG_BASE_URL`**）。
- `tests/test_assistant_api.py`：接口与输出安全回归测试，当前共 12 项（详见第 9 节）。

前端（`code/frontend/src/`）：
- `assistant/api.ts`：`/api/assistant` 请求 + SSE 解析。
- `assistant/types.ts`：会话/消息/引用/技能等契约。
- `assistant/markdown.ts`：早期零依赖 Markdown helper，当前助手回答正文由 `@copilotkit/vue` renderer 处理；文件还在，但不是现行正文入口。
- `views/AssistantView.vue`：三栏界面 + 技能商店 + 执行活动折叠面板 + 停止生成 + CopilotKit 消息渲染。
- `router/index.ts`、`layouts/MainLayout.vue`：`/assistant` 入口与顶栏「慧眼助手」。

文档：`docs/ai-assistant/README.md`（接口契约、SSE 事件表、时序图、运行配置、开源 UI 选型与输出安全说明）。

## 3. 关键决策与原因

1. **历史决策：不引入第三方 Markdown 库，手写零依赖子集**（`markdown.ts`）。本轮已重新评估并采用 CopilotKit Vue 官方 assistant message renderer；现有旧 helper 暂留但不再负责助手正文渲染。新依赖及取舍见第 9 节。
2. **不换栈到 React + assistant-ui**。原因：全仓是 Vue 3 + Element Plus，换 React 成本大且与团队协作冲突；Vue 生态无 assistant-ui 级库，故「保持 Vue + 吸收成熟交互细节」。
3. **右栏从「服务状态/LIVE TRACE」改为「审核技能」商店**。原因：用户明确要求去掉服务状态等装饰、要业务向的 skill；技能取自 AGENTS.md 中专项审核 Agent 的能力项（节假日/汇率/提单验真/制裁名单/法规检索），外加「单据比对」。每个技能点击后发送结构化 prompt，要求模型以 Markdown 表格输出。
4. **步骤时间线/工具检索轨迹**：后端发送公开的固定 step 和 `tool` 状态；前端执行期间展开显示，完成后折叠。当前工具轨迹随步骤写入历史；不得把模型内部推理当作执行事件显示。

## 4. 踩过的坑（重要，供后续参考）

1. **本机沙箱没有 Node.js/npm**，无法 `npm run build`。解决：下载便携版 Node（`node-v20.18.1-win-x64.zip`）解压到 `C:\Users\28462\AppData\Local\Temp\node20\`，用其中的 `node.exe`/`npm.cmd` 跑构建。该目录在系统临时目录，可能被清理；后续需要构建时可用系统 Node 或重新下载。
2. **模型 tool-call JSON 回显 bug（已修）**：经 CCSwitch 的 `gpt-6.1-sol` 在真正调用 `search_knowledge_base` 工具**之前**，会把工具参数 `{"query":"..."}` 当作普通文本 delta 输出，拼进 `answer` 导致正文开头出现原始 JSON。修复：`assistant_service._strip_tool_echo()` 用 `json.JSONDecoder().raw_decode` 剥离前导的工具参数 JSON（仅当含 query/question/input 等键、且剥离后仍有正文时才删）。已加单测，并用真实模型 SSE 复测确认。
3. **openai-agents 0.4.2 与 openai>=2.45 不兼容**（上一会话发现）：新版 openai 的 usage 字段让 Agents SDK 初始化失败。已锁定 `openai==2.44.0`（`requirements.txt` 有注释）。
4. **我临时写的 Python SSE 预览代理会缓冲整个响应**（`urllib.request.urlopen`），导致浏览器里流式不渐进。这是预览代理的局限，**不是应用 bug**；真实 Vite dev server 的 `/api` 代理能正常流式。验证 SSE 应直接打后端 8000 端口。
5. **流式时整个页面被拉长（已修）**：根因是页面用 `min-height` 而非固定 `height`，消息增长把整个 main 撑高。修复：`.assistant-page { height: calc(100vh - 60px); overflow: hidden }`，`.chat-column/.message-list` 用 `flex:1; min-height:0; overflow-y:auto`，`.composer-wrap { flex: 0 0 auto }`。已实测 `document.scrollHeight == window.innerHeight`、composer 贴底不动，只有消息区内部滚动。
6. **RAG 未接线（待另一个会话完成）**：`app/rag_service.py` 之前不存在、`config.py` 无 `RAG_BASE_URL`，`assistant_service._rag_search()` 里 `from .rag_service import RAGClient` 总是 ImportError 而回退本地证据。前端 `capabilities.rag_available` 由 `settings.RAG_BASE_URL` 决定，接上后会自动从「本地证据检索」变成「知识库已连接」。
7. **历史状态**：此前记录的“tool 轨迹不持久化”已过时。当前 `stream_assistant()` 将工具步骤汇总写入消息 `steps`，测试覆盖历史读取；历史记录里缺少步骤的不会补造。

## 9. 2026-10-19 续作：对话输出安全与成熟 UI

### 本轮完成

- 对比了 CopilotKit Vue、assistant-ui Vue 和 Open WebUI。选用 [`@copilotkit/vue`](https://github.com/CopilotKit/CopilotKit) 官方 assistant message renderer，保留项目自己的 FastAPI SSE、JWT、会话存储、HSBC 百炼配置与 RAG 工具边界；assistant-ui Vue 当前包成熟度/适配方式不适合直接替换现有传输层，Open WebUI 则会带入另一整套后端、认证和会话栈。完整评估见 `README.md` 的“开源 UI 选型记录”。
- `AssistantView.vue` 使用官方消息 Markdown renderer；执行期间显示审核助手、上下文、证据检索等公开活动，默认展开；完成后自动折叠，用户仍可点击查看。加入停止生成按钮，并将 `AbortSignal` 传给 SSE fetch。用户消息保持纯文本。
- 安全修复模型思维内容泄漏：`run_agent_events()` 不再转发 Agent SDK 的原始 `raw_response_event` 文本，只在运行结束后检查 `final_output`，再以 `delta` 分片发送；网关报错时丢弃不完整原始片段并走既有本地演示兜底。请注意：这保护隐私，但最终回答不是逐 token 流式，实时反馈来自 step/tool 活动事件。
- 新增 `_safe_final_answer()` 常见内部分析/工具规划标记检查。命中内容时不发送模型文本，走已有本地兜底回答。`GET /sessions/{id}` 对命中标记的旧助手记录返回“已隐藏”占位提示；不更改数据库原始记录。前端渲染与复制功能也应用同一类检查，避免旧历史内容继续显示或复制。
- 执行步骤历史与工具步骤持久化行为已有测试。新增回归用例覆盖原始思维 delta 不外发、内部推演 final answer 丢弃、旧历史 API 脱敏。
- 依赖由 `package.json` 与 npm `package-lock.json` 管理，清除了本轮安装意外产生的 pnpm 锁文件；移除了不再被助手 UI 使用的顶层 `marked`、`dompurify` 依赖。不要提交构建生成目录或 RAG 同事改动。
- UI renderer 通过异步组件导入。当前生产构建中相关最大块约 1.67 MB（gzip 约 463 KB），首轮回答时会额外下载；上线前要在汇丰电脑及目标部署网络实测。如果超出网络/加载预算，可再评估更细粒度的官方子组件入口或其他 Vue 方案，不要未经测量直接扩大首屏包。

### 交接注意事项

- 内部推理检测是纵深防护，不是完整的 reasoning-channel 分类器。HSBC 百炼具体部署模型仍需做针对性红队/回归测试，确认不会把私有推理放进 `final_output`。新增模型或更换网关后应测试原始流、工具参数回显、最终答复三类内容。
- 页面已折叠的是可公开执行状态，不是模型私有思维链。不要将 chain-of-thought 设计成“展开后可看”；只展示工具调用、检索状态、结果数和简洁活动摘要。
- 该提交不代表 RAG 接线已完成。RAG 状态、配置和知识库索引请与负责 `code/rag-service/` 的同学按共享接口继续对接；慧眼助手仍只通过自己的 RAG client/tool 边界调用。
- 团队同学拉取后需按 `README.md` 的汇丰运行配置获取团队 API 凭证；不要依赖个人 CCSwitch，也不要在仓库或前端配置中保存 API Key。
