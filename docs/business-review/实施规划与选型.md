# 贷款文件审核实施规划

## 目标与范围

首期跑通第 8、9、10 套贸易背景材料的“字段证据 → 强校验 → 待复核 → 人工决定 → 留痕归档”闭环。沿用现有主站任务、OCR 接口、规则结果和审核工作台，避免另建一套案件或聊天系统。流贷、固贷、车贷待主流程验收后再扩展。

当前实施只在独立稳定分支 `lfc-business-review`；第 8/9/10 套各自的目标异常未由规则结果和明确来源证据验证命中、失败关闭回归未通过且业务审核人未签收之前，不合入 `lfc`。当前决策模型、LLM runtime 和独立校准数据都未配置，流程按不可用状态失败关闭，不生成模拟模型结论。

## 实施步骤

| 阶段 | 交付 | 验收证据 |
| --- | --- | --- |
| 1. 规则梳理 | 将 V2 与字段梳理表整理成规则目录；冲突进入台账 | 每条规则标出来源、可编码字段、边界、人工/外部依赖 |
| 2. 强校验 | 对齐来源表逐项核对已编码规则，补齐合同/订单/报关编号、主体、金额、数量、单价等确定性比较 | 正例、反例、缺字段和多文件测试；未解析字段不得落为通过 |
| 3. 决策流程 | 规则后由代码显式控制指定模型节点、输入摘要和状态迁移；强失败固定保留；字段变化使旧运行失效 | 未运行、强失败未处置、证据不足、输入过期、模型/LLM 缺席都不能自动归档 |
| 4. 审核工作台 | 展示对象关系、规则差异、来源定位、AI 参考状态和处置入口 | 审核人完成更正、补件、例外及最终提交流程 |
| 5. OCR 联调 | 对目标 PDF 固定 200 DPI 跑本地 PaddleOCR；逐阶段量渲染、模型初始化、OCR、字段归一与证据定位；先证明性能调参没有输出变化，再运行限定材料 | OCR 摘要变化不得默认采用；关键字段和规则证据定位可复查；扫描失败分类与延迟入测试基线 |
| 6. 决策模型 | 仅在预定义软判断节点发送结构化输入；校验输入摘要、schema、候选标签、置信度、模型/校准版本及证据 ID | 仅来自独立标注集的校准 ≥90% 输出可被该节点接受；失配、低置信、版本未知、超时或过期输入均拒绝并转 LLM 参考或人工 |
| 7. 大语言模型参考 | 只有决策模型未配置、低置信/输出无效或节点本身需要证据解释时，才由工作流请求已授权的 OpenCode runtime | 限定输入证据并核查引用；只提供参考、不产生贷款结论；LLM 不可用时转人工并保持未决 |
| 8. UAT | 业务人员复核 8/9/10、边界及补件案例 | 签字验收；未完成能力明确列为缺口 |

## 技术选型和取舍

| 能力 | 选型 | 取舍 |
| --- | --- | --- |
| 文档 OCR | 复用仓库 code/ocr_service 的 PaddleOCR CPU 服务和现有字段解析接口 | 先用本地处理，贷款材料不发送到未授权云 OCR；扫描件实测结果仍需联调验收 |
| 审核流程 | 复用 FastAPI 任务接口、SQLAlchemy 状态和审核人动作，业务层只定义本模块状态及归档门槛 | 目前是有限、短链路的顺序流程；不引入通用 Agent/编排框架 |
| LLM | 复用已提交的 OpenCode SDK 助手运行时，使用授权任务证据并保留引用 | 输出是参考意见，不拥有自动放行权限；运行时/汇丰模型 API 未配置时明确返回不可用 |
| 决策模型 | 暂不选定具体模型；等待可用服务和独立标注数据后按校准指标选型 | 当前没有模型端点或金标准数据，不能声称达到 90% |

编排调研以官方资料为准：LangGraph 提供 checkpoint/persistence 和 interrupt，适合需要图状态恢复及人工暂停的 Agent 工作流；Temporal 提供可长期恢复的 durable workflow 和 signal，适合跨服务、长等待、重试及补偿流程。当前审核主链条短、顺序明确，任务和人工处置状态已由数据库持久化，使用项目内窄范围状态迁移即可；当流程需要跨日等待、分布式重试或多服务补偿时再做试点，避免为三步流程引入独立运行集群。

- [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence)
- [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts)
- [Temporal Workflows](https://docs.temporal.io/workflows)
- [scikit-learn probability calibration](https://scikit-learn.org/stable/modules/calibration.html)
- [Alibaba Cloud Model Studio vision API](https://help.aliyun.com/en/model-studio/qwen-vl-compatible-with-openai)：文档说明兼容接口可用 `image_url` 传入 Data URL 图片；本项目只适配协议，不默认选择云端供应商，实际环境必须由汇丰授权端点、模型及外发策略决定。
- OCR 使用的上游依赖、许可及 CPU 安装方式以 [PaddleOCR 官方文档](https://www.paddleocr.ai/latest/en/index.html) 和当前项目 code/ocr_service/pyproject.toml 为准；上线前还要核对模型下载来源、许可和汇丰环境的外发策略。

## 资源与风险

- OCR：使用本地 CPU 与本地模型缓存；首启下载模型需要网络。百度云 OCR 会外发文件，本期不启用。
- OCR 兜底：主解析适配器已实现但默认关闭。只有经授权并配置 `OCR_VISION_ENABLED=true`、`OCR_VISION_BASE_URL`、`OCR_VISION_API_KEY` 和 `OCR_VISION_MODEL` 才会发送低质量页面；服务返回候选行（`score=0`、无坐标），必须复核，不能作为强校验通过证据。会议记录提到的勾选/遮挡误读风险仍需影子评测；当前没有凭证，因此本轮真实材料不会外发。
- LLM：需要已部署且可连通的 OpenCode runtime、汇丰模型 API 凭证和授权证据范围；凭证只能在服务端配置。
- 决策模型：需模型端点、版本管理、独立标注、校准/分层评测和回滚能力。缺少任一项时不进入自动决策路径。
- 业务规则：第 8–10 套只能证明这些已知造错点是否被发现，不能代表总体准确率或真实生产分布。
- 规则覆盖缺口：当前解析器尚无授信函日期、提款申请日、利率、计息期等字段，相关 V2 对照规则无法可靠运行；节假日、汇率和外部真实性也需授权数据源。补齐字段解析和规则前保持待复核。
- 当前资料中的买方规则有冲突；按架构文档标记待业务确认，不静默定口径。

## Workflow 与模型输出校验

工作流由业务服务的显式状态迁移控制，不使用通用 Agent 自由规划、调用工具或决定贷款结果。节点顺序为：解析/证据质量门 → 确定性强规则 →（仅对预定义软判断）决策模型 →（决策模型缺席、输出无效或置信度低于 90% 时）LLM 带证据参考 → 人工审批。明确强规则失败与关键证据缺失都固定转人工；LLM 无权清除失败或将贷款结论改为通过。

决策模型接入契约至少要包含：任务/规则输入摘要、字段及来源证据 ID、允许的候选标签、概率/校准置信度、模型版本、校准器/评测集版本和请求关联 ID。代码校验 schema、枚举、数值边界、输入摘要、模型/校准版本和证据归属；拒绝自由文本、未知标签、NaN、置信度未校准、引用任务外证据、超时响应和陈旧审核运行。节点调用与结果、版本、拒绝原因及后续人工动作写入审计记录。任何校验失败都不转为 pass。

## 测试基线

受限真实回放的分母为 10 份目标规则必要材料（第 8 套主体/收款方 4 份，第 9 套金额链 3 份，第 10 套合同号关联 3 份）。验收程序仅输出每份的类型、耗时、OCR 字符/块数量、字段槽位数、有值字段数、具备页码和四点 bbox 的字段数、失败分类和套件目标规则命中状态；不记录文件名、OCR 正文或字段值。目标命中必须同时满足目标规则状态为 `fail` 且存在明确标记为 `bad` 的证据行，单元测试的合成错误不能替代真实材料命中。

首次 10 份回放已完成，端到端耗时 1,424.7 秒，目标命中 2/3；第九套金额规则因合同/订单/发票金额未提取而 `skip`。首次支付指令调用使用 180 秒默认上限，后续单份 `/file/detailed` 实测耗时约 260–271 秒并成功，因此后续缺失样本补测上限设为 600 秒。当前只补齐首次超时的支付指令，不重跑其余已验证材料；首次报告没有保存其他样本逐个规则关键字段计数，这部分标明缺口，不从通用字段计数推断。

失效分类至少区分 OCR 无文本/无块、OCR 有内容但字段抽取为空、字段有值但页框定位不足、规则明确命中、模型服务/版本/校准缺失、模型输出 schema/证据/输入摘要无效、LLM 不可用。失败关闭回归验证上述状态不会归档，且硬规则失败不能被模型/LLM建议覆盖。每轮同时记录 10 份材料端到端耗时和按单据类型耗时，采用固定机器、200 DPI、模型版本及线程/batch 参数记录可比较基线。

## 完成定义

代码测试、OCR 识别和业务验收分开报告。只有三套实际材料的目标错误均由原文证据复现、未触发错误放行、人工流程可闭环且业务人员确认后，首期主流程才算业务验收通过。模型层和外部专项能力未就绪时单独列为资源缺口，不影响对已完成强校验能力的如实报告。
