# 第 8–10 套材料测试与验收

## 测试数据

真实材料位于共享文件夹 01_汇丰业务文件，测试程序从本机目录读取。通过环境变量 HBCN_BUSINESS_MATERIALS_ROOT 指定该目录；原 PDF、OCR 全文、客户/供应商名称和账号均不得复制进 Git、测试日志或截图。

| 数据集 | 预设改动 | 必须验证 |
| --- | --- | --- |
| 第八套 | 客户/供应商名称变更 | 文件间卖方、支付收款方关系；买方与借款人冲突按待复核呈现，不能由 AI 自动通过 |
| 第九套 | 合同价格变更 | 合同、订单、发票、报关及支付金额/单价关系；在材料未能支持确定关系时转人工 |
| 第十套 | 发票及报关单合同号变更 | 合同号及跨文件编号关联被发现；报关协议号按允许关联规则比较 |

三套每套包含授信函、商业合同、形式发票、报关单、提款指令、支付指令和运单。未提供商业订单的规则要区分“可选文件缺失”与“已有文件缺少关键字段”，不能把跳过当作通过。

## 测试步骤

1. 在本地启动 code/ocr_service，通过后端现有解析器逐个处理 PDF；验收脚本默认只选择三个目标强规则所需的 10 份材料，原文留在本机临时目录。
2. 测量 PDF 页渲染、模型初始化、OCR 推理、字段抽取和证据定位；只输出单据类型、字符/块数量、字段槽位/有值/真实定位计数、失败分类及耗时，不输出原文、文件名或字段值。
3. 将解析字段提交到规则引擎。目标命中必须同时满足目标规则返回 `fail` 且存在标记为 `bad` 的证据行；缺字段、OCR 空结果或无原文位置都算失败关闭，不能当作命中或通过。
4. 验证买方口径冲突、模糊价格、商品语义等事项按“强规则 → 指定决策模型节点（仅校准置信度 ≥90% 且输出校验有效时接受）→ 低置信/无效/未配置时 LLM 参考”流转；模型不可用时保持待复核，不生成模拟建议。
5. 修改字段或补件后，确认旧审核运行失效并重新执行。
6. 验证强校验阻断、人工例外理由、补件及最终归档的权限和审计记录。

## 验收门槛

| 门槛 | 通过条件 |
| --- | --- |
| 解析 | 三套扫描件关键字段可追溯到原文页和坐标；低于 80% 置信度、视觉 OCR 候选及漏识项明确待复核 |
| 目标错误检出 | 第 8、9、10 套分别命中对应主体、价格、编号规则 |
| 不误放行 | 任一明确强校验 FAIL、证据缺失或过期运行均不能直接归档 |
| AI 边界 | AI 参考包含可回查证据；不能改写强校验结果或代替人工审批 |
| 审计 | 人工处置人、时间、动作、理由和被处置规则项可查询 |
| 决策模型 | 独立测试集与校准报告证明使用门槛；无数据时标记未验收 |
| 业务签收 | 审核人员复核规则口径、异常结果和补件/例外操作并签收 |

## 本轮实际结果

首次 10 份目标材料回放于 `lfc-business-review` 隔离工作树执行。PDF 只从共享目录本机读取，临时副本在脚本退出时清理；报告不保存原文、字段值或文件名。本地 OCR 服务只监听 `127.0.0.1:7889`，材料没有发送到外部服务。

首次回放使用后端默认 OCR 客户端超时 180 秒。两份支付指令在客户端超时后被记录为空结果；后续以单份请求、600 秒上限补测，均成功返回。这两份不是材料空白，而是请求上限短于 OCR 实际耗时。

### 目标规则结果

| 套件 | 目标规则 | 结果 | 证据行 / bad 行 | 判断 |
| --- | --- | --- | ---: | --- |
| 第八套 | `SUPPORTING__SELLER` | `fail` | 3 / 1 | 命中预设主体差异 |
| 第九套 | `SUPPORTING__AMOUNT` | `skip` | 0 / 0 | 未判定，不是通过；合同、订单、发票侧没有可比较金额 |
| 第十套 | `SUPPORTING__CONTRACT_NO` | `fail` | 3 / 2 | 命中预设编号差异 |

按预设错误套件计算，目标差异实测命中 2/3（66.7%）；第九套为未判定，不能计为通过。两次 `fail` 均带有 `bad` 证据行。第九套缺少商业订单，且合同及形式发票金额未提取；即使补出的支付金额可定位，也不能单独完成金额链比较。

### 仅补测缺失支付指令

遵照不重复处理已验证材料的要求，仅对首次超时的支付指令做单份定向请求，未重跑其余 8 份材料。每个请求上限为 600 秒，服务串行处理。

| 套件 | 接口 | 状态 | 耗时 | OCR 字符 / 块 | 字段槽位 / 有值 / 有定位 | 目标字段有值 / 有定位 |
| --- | --- | ---: | ---: | ---: | ---: | ---: |
| 第八套 | `/extract` | 200 | 218.9 秒 | 不返回明细块 | 5 / 5 / 不适用 | 未采集 |

支付指令证实 OCR 可在 180 秒之后成功完成。第八套和第九套的单份补测没有重跑规则链；根据首次回放，两个套件的完整目标规则结果仍分别为第八套 `fail`、第九套 `skip`。

### 500 与字段级统计边界

首次回放期间 `/file/detailed` 曾出现一次 HTTP 500。随后对第十套商业合同、形式发票和报关单逐份定向重放，均返回 HTTP 200，没有复现异常；原始 500 没有保留响应体或堆栈，因此不能可靠指认那一次的具体异常类。解析服务现在仅记录异常类名，500 响应提供结构化 `error_type` 和通用错误文本，不写异常消息或临时路径；相关接口测试通过。

首次回放保存的是每份材料的通用解析字段计数，没有保存每个规则关键字段的独立有值/定位计数。为避免违反“不重跑已验证材料”的要求，本轮不补跑其余 8 份材料；新增的验收脚本会在后续必要回放中单独输出目标关键字段槽位、有值数和定位数。当前可确认的关键字段专项计数只有第九套支付金额 1/1 有值、1/1 有定位。
