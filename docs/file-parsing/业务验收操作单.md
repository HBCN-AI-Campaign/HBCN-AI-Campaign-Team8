## 按业务顺序检查

| 步骤 | 操作 | 应看到的结果 / 记录 |
|---|---|---|
| 1 | 经办登录，发起审核，手动选择该目录7份PDF，开始智能识别 | 实际文件名、类别及进度；分类不符时按原件选类并填写依据。文件选择必须由用户完成，当前工具不能完成原生文件上传 |
| 2 | 识别后查看金额、币种、日期、合同号及待核实项 | 字段分槽且有原文入口；不将任意日期混入提款日，不把单价作总额；可用值和未决候选分明 |
| 3 | 打开原件定位，查看勾选/删除、数量单位和授信分配疑点 | 原件页码与证据可追溯；不清楚的选项、借款主体、单位不默认确认，不为继续流程编造值 |
| 4 | 保存待核实任务；若页面有必填校验，记录具体阻断，不填假资料绕过 | 提交保留原解析编号和核实说明；刷新后来源及未决状态还在。选择客户不能替代原件的法定借款主体核实 |
| 5 | 审核账号查看任务，在业务审核页执行“审核当前材料” | 规则消费有来源的字段；B01付款覆盖差异不通过；借款主体等未决继续显示 |
| 6 | 尝试完成审核，查看历史原件和核实留痕 | 有未决/不通过时禁止完成；补正必须保存新原件及新解析凭据，旧记录可追溯 |

不使用“一键载入”替代步骤1：该按钮的内置样本组合与本次7份原件选择不同。不得为了消除红项强行确认原件没给出的事实。可先只完成步骤1并告知任务/解析编号，由工程侧继续检查回执。

核实控件另检查：更正一个已识别值后应立即显示“已更正，待填写说明”，未填有效值和说明时不能继续创建/提交补件；点“恢复识别值”应恢复完整原值并清空本次说明，金额尾零也保留。填写说明后显示“核实说明已填写”，提交仍需服务器复验；新一轮解析不能带入上一轮说明。此检查应在隔离数据进行，不为了演示而更改真实业务结论。
