## 📋 问题发现

在代码审查过程中发现，AI 助手模块的实际实现与团队原始技术规划存在偏差：

| 维度 | 原始规划 | 实际实现 | 状态 |
|------|---------|---------|------|
| Agent SDK | **OpenCode SDK** ([github.com/anomalyco/opencode](https://github.com/anomalyco/opencode)) | `openai-agents==0.4.2` (OpenAI 官方 SDK) | ❌ 偏离 |
| 前端 UI 框架 | Vue 3 + Element Plus 原生组件 | Vue 3 + Element Plus + **CopilotKit** (`@copilotkit/vue@1.79.1`) | ⚠️ 偏离 |
| 开源性 | 完全开源 | 依赖 OpenAI 官方 SDK（协议不明确） | ❌ 偏离 |

---

## 🔍 偏差根因分析

### 1. OpenAI Agents SDK 被错误选择的原因

**推测原因**：
- AI 编码助手（Cursor/Copilot）在生成代码时，优先选择了**文档更丰富、社区更主流**的 OpenAI Agents SDK
- 开发者在快速原型验证阶段，未严格对照 `docs/RAG实施规划.md` 的技术选型表
- OpenCode SDK 的知名度相对较低，搜索引擎结果更少，AI 助手可能未能识别

**证据**：
- `docs/RAG实施规划.md` 第 25 行明确写着："检索模式 | RAGFlow Hybrid Retrieval；**Agentic 编排由 OpenCode SDK 负责**"
- 第 125 行参考链接：[OpenCode](https://github.com/anomalyco/opencode)
- 但 `code/backend/requirements.txt` 第 11 行却是 `openai-agents==0.4.2`

### 2. CopilotKit 前端依赖的问题

**问题**：
- `@copilotkit/vue@1.79.1` 体积巨大（1.67 MB，gzip 463 KB），影响首屏加载
- 引入了外部 UI 框架，与项目统一的 Element Plus 设计语言不一致
- 增加了不必要的依赖复杂度

**原始规划**：
- `docs/ai-assistant/README.md` 明确要求："前端沿用仓库已有的 Vue 3 + Element Plus，**不新增 React 或另一套状态系统**"

## 📊 OpenCode vs OpenAI Agents SDK 对比

| 特性 | OpenCode SDK | OpenAI Agents SDK (当前) |
|------|--------------|--------------------------|
| **开源协议** | ✅ Apache 2.0 / MIT | ⚠️ OpenAI 官方，协议不明确 |
| **依赖灵活性** | ✅ 兼容任何 OpenAI-compatible API | ⚠️ 绑定 `openai==2.44.0`（版本锁定） |
| **社区驱动** | ✅ 开源社区维护 | ❌ OpenAI 官方闭环 |
| **文档丰富度** | 🟡 中等（GitHub README + Examples） | ✅ OpenAI 官方文档完善 |
| **比赛加分** | ✅ 开源技术栈有加分 | ❌ 闭源依赖可能减分 |
| **企业部署** | ✅ 无厂商锁定 | ⚠️ 可能受 OpenAI 服务条款限制 |

## 📌 经验教训

1. **严格遵循技术选型文档**：`docs/` 目录下的规划文档是团队共识，不应随意偏离
2. **AI 助手生成代码需人工审核**：Cursor/Copilot 会优先选择主流方案，不一定符合项目特定需求
3. **定期 Code Review**：及早发现技术选型偏差，避免后期大规模返工
4. **文档即契约**：技术选型一旦确定，应在 `requirements.txt`、`package.json` 等配置文件中体现
